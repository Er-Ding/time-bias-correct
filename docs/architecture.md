# 第一版模块与数据边界

> 本文保留早期模块与数据边界说明。当前执行顺序和新增的初始点、代表点、代表轨迹文件见 [点聚类流程说明](point_clustering_workflow_20260909.md)，不要用下文早期步骤作为当前执行证据。

## 三条互相隔离的链路

### 1. 场景和仿真数据准备

```text
生成配置（含 simulation，仅生成与独立评估侧可读）
        │
Sionna RT 原始场景与传播路径
        │
        ├─ 原始 vertices/faces/objects
        │          → 固定高度切三角面 → scene_2d.json + scene_bev.png
        │
        ├─ cir(normalize_delays=False)
        │          → 正面、固定高度路径筛选 → 带公共时延偏差的在线 CSI
        │
        └─ DeepMIMO V4 转换 → 独立保存的数据集产物
```

DeepMIMO 转换后的 `Dataset.scene` 不再进入定位地图。当前转换器会先给每个连通
物体求二维凸包；凹形建筑或同一对象里的分离组件可能被一条并不存在的长边连接。
定位地图改为读取 `sionna_exporter` 写出的 `sionna_vertices.pkl`、
`sionna_faces.pkl` 和 `sionna_objects.pkl`，逐个原始三角面与固定高度平面求交线。
因此只会留下三角网格里真实存在的墙，不会用两个远处顶点补出“假墙”。

生成阶段还会做一次反向一致性检查：

- 对直射路径，从 BS 沿真实到达角反向走到 UE 前，不能提前撞墙；
- 对反射路径，反向遇到的第一面墙必须落在 Sionna 给出的最后一个交互点附近；
- 地图范围预先由 `scene.localization_bounds_m` 固定；UE、BS 和全部保留路径交互点
  必须已经位于其中，否则生成自检失败，范围不会随真值扩张；
- 检查结果写入 `generation_manifest.json`，未通过时不会继续生成定位输入。

DeepMIMO V4 产物仍然保留，它用于验证数据格式、保存路径参数和支持后续实验；
“不用 DeepMIMO 场景做二维墙”不等于“不生成 DeepMIMO 数据”。

### 2. 在线定位

```text
不含 simulation 的定位专用配置
       │
生成清单中的批次、场景和在线 CSI 来源记录
       │
scene_2d.json
       │
measurement.npz ─→ 2D-MUSIC ─→ AOA/Delay 峰及扰动峰集合
       │                               │
       └──────────────────────→ 反向镜面追踪
                                       │
                         p_ik(beta)=a_ik-beta*u_ik
                                       │
                         同一观测的候选解释互斥
                                       │
                         多路径位置和公共偏差联合求解
                                       │
                                  μ、Σ、b
```

定位阶段接收定位专用配置、生成清单、`scene_2d.json` 和
`data/online/measurement.npz`。生成清单只用于确认场景和在线 CSI 的路径、内容
指纹及批次关系；定位能够看到清单里的真值路径和内容指纹元数据，但不会打开真值
文件，也不会把真值内容复制到定位结果。定位配置加载器和 `localize()` 会在创建输出前
双重拒绝任何含 `simulation` 的完整生成配置，六个合法配置段内部也只允许已定义
字段；定位函数没有真值文件参数，也拒绝读取名为 `truth` 的目录。在线 NPZ 必须
严格只有 `csi_observed`、`subcarrier_frequencies_hz`、
`carrier_frequency_hz`、`antenna_spacing_m`、`bs_position_m`、
`bs_boresight_rad` 这 6 项，多一个或少一个都会停止。UE 是单天线发射端，BS 是
阵列接收端；`radio.bs_position_m`、BS 朝向和阵列参数是公开先验，生成用的
`snr_db` 不会进入定位配置。在线 CSI 的最后两维固定为“BS 阵元、子载波”。

主定位入口不会只看三个文件指纹。它还严格检查生成清单版本、支持的生成阶段、
上行方向、绝对时延、原始三角网格与固定范围、传播机制，以及场景名称/范围、
CSI 尺寸、频率间隔、载频、阵元间距、BS 位置和朝向。场景 JSON 的顶层和每条墙
也采用固定字段集合；墙端点必须严格为二维有限坐标。这些检查不使用 UE、注入偏差、
真实路径数量或场景自检结果来决定是否定位。

### 3. 独立评估

```text
localization_result.json + data/truth/ground_truth.npz
                         → evaluation/metrics.json
```

评估只在定位完成后运行。UE 真值、干净 CSI、真实路径编号和注入偏差不会回传给
定位模块。一键脚本只在生成复用检查和独立评估阶段打开真值内容；它启动定位命令时
传入定位专用配置、生成清单、场景和在线 CSI。三个阶段严格按“生成或复用 → 重新定位 →
重新评估”的顺序执行，避免新的定位结果配上旧的误差文件。

每次定位还会生成唯一运行编号，并记录补齐默认值后、不含 `simulation` 的定位配置
快照，以及生成批次、场景、在线 CSI、定位结果的 SHA-256 文件指纹。评估必须先
确认定位结果与同目录清单完全一致，并确认真值与场景、CSI 同属该生成批次，然后在
指标中写入该运行编号、批次编号、结果指纹和真值指纹。定位清单还会保存完整生成
清单的指纹：批次编号标识三个核心文件，清单指纹另行绑定上行、绝对时延、地图和
传播模型等声明，二者不能互相替代。再次定位并准备发布新产物前，旧主结果、6 个
诊断文件、定位配置、指标和路径已改写的旧清单会先归档到
`evaluation/history/<旧运行编号>/`；离线闭环还归档该次输入和生成清单。新清单
标记为“等待重新评估”，固定
`metrics.json` 保持不存在，直到新评估成功。评估输出也不能覆盖历史目录或清单所
保护的输入、配置、结果和真值文件。

上述完整历史格式只适用于归档机制加入后新产生的记录。run11 中编号为
`691931db-55cb-4e92-b2ba-bb74c39dfd67` 的更早目录只有旧清单和旧指标，保留作追溯，
不视为可独立验证的完整归档。

`run_localization.sh` 和一键 smoke 脚本会为每次定位原子创建一份不可覆盖的运行回执；
底层 Python 接口在显式传入回执路径时采用同样行为。评估必须显式传入该次运行编号，
并在打开真值前同时核对定位清单和结果中的编号；因此定位与评估之间即使插入另一
次运行，也只会停止，不会把两次结果拼在一起。

评估输出固定为输出根目录下的 `evaluation/metrics.json`。指标和写回后的定位清单
作为一组发布：任一文件提交失败，两者都会恢复到评估前状态，避免留下新指标配旧
清单或旧指标配新清单。

同一个输出目录的生成、定位和评估共享一个跨进程排他锁，从读取到最终写回都不会
与另一进程交错。场景、NPZ 和 JSON 先写到同目录临时文件，同步完成后再整组或原子
发布；评估在写回前还会再次确认定位清单的运行编号和完整内容没有变化。

## 到达角约定和正面先验

Sionna 的 `phi_r` 是接收端看到的全局到达方向。MUSIC 使用 BS 阵列局部角度，
定位前再加上 BS 朝向变回地图全局角。当前均匀线阵的阵元沿局部横轴排列，空间
相位与 Sionna 保持同一正负号。

均匀线阵本身无法从相位中区分正面方向和背面的镜像方向。第一版通过
`radio.front_facing_only: true` 明确采用正面先验：生成 CSI 时只保留相对 BS
朝向落在 `[-90°, 90°]` 的路径，MUSIC 也只搜索这个范围。若以后要覆盖 360°，
必须更换能分辨前后的阵列，或让反向追踪同时保留两侧解释，不能只删除角度限制。

## 绝对时延和无混叠范围

观测模型是：

```text
观测 TOA = 完整几何传播时延 + 公共时间偏差 + 测量误差
```

所有 Sionna `cir()`/`cfr()` 调用都强制使用 `normalize_delays=False`，因此不会
把首径减成零。公共偏差通过同一组子载波频率施加，正偏差对应更大的观测时延。

保留绝对时延只是数据含义正确，不代表任意大时延都能从等间隔子载波中恢复。
子载波间隔为 `Δf` 时，频域相位每 `1/Δf` 重复一次；当前频率构造下，这个范围
等于“子载波数/带宽”。MUSIC 搜索宽度必须小于该范围。定位入口会先检查，超出就
明确报错，避免把同一路径的周期副本当成另一条路径。

## MUSIC 的两个“路径数”

这两个配置不能混为一谈：

| 配置 | 实际作用 |
|---|---|
| `music.signal_subspace_rank` | 计算 MUSIC 时，信号子空间保留多少个成分 |
| `music.num_paths` | 从伪谱中最多取多少个基准峰送入定位器 |

仿真 CSI 中可能含有很多较弱路径，但第一版只希望向定位器输出少量清楚的峰。因此
信号子空间阶数可以大于输出峰数。把两者强行设成同一个数，会把未建模的真实路径
留在“噪声”一侧，进而扭曲谱峰。MUSIC 伪谱值只用于同一张谱内找峰和排序，不能
直接当作路径概率。

## 扰动、漏检和协方差

基准峰只产生中央解，不会再次充当一条扰动样本。对观测 CSI 做可复现的小幅
扰动后，每次都会重新执行 MUSIC、整组峰配对、反向追踪和联合求解。

峰集合配对允许两种现实情况：

- 多出来的虚假峰可以保持“不匹配”，只进入诊断，不会被强迫参与定位；
- 若一次扰动漏掉了某条基准路径，该次少信息结果记为失败，不进入最终均值。

至少两次扰动得到完整解时，最终 `mu` 和公共偏差由这些成功解加权计算。协方差
使用全方差公式，同时包含“每次解自身的不确定度”和“不同扰动解之间的离散程度”；
随后按 `请求扰动次数 / 成功次数` 放大。若只有零次或一次成功解，则退回基准解的
均值和偏差，并按失败比例放大基准协方差。这样不会把单次偶然解解释成稳定分布。
全部成功解和失败原因分别保存在 `uncertainty_solutions.npz` 与
`bootstrap_diagnostics.json`，方便检查高斯是否掩盖了多簇结果。

## 主要文件

| 文件 | 作用 |
|---|---|
| `scene.py` | 原始 Sionna 三角网格固定高度切片、二维墙线和坐标标定 |
| `signal.py` | CSI 合成、公共时延偏差、AOA/Delay 二维 MUSIC |
| `raytrace2d.py` | 离线闭环使用的二维正向镜面路径 |
| `candidates.py` | MUSIC 样本的反向追踪、有效偏差区间和候选聚类 |
| `solver.py` | 候选互斥、多路径位置/距离偏差稳健联合求解 |
| `adapters.py` | DeepMIMO V4/Sionna 数据字段、绝对时延和互易适配 |
| `sionna_generation.py` | Sionna Munich、原始网格地图、DeepMIMO 产物和在线 CSI |
| `contracts.py` | 生成清单外壳以及场景、在线 CSI 和公开物理参数的一致性校验 |
| `pipeline.py` | 分阶段产物、真值隔离、整组峰配对和 μ/Σ |
| `provenance.py` | 配置快照、运行编号、批次关系、同源读取和输入输出文件指纹 |
| `cli.py` | 所有 `.sh` 脚本共用的命令行入口 |

## 现在能证明什么

run11 小规模 Munich smoke 已从零真实生成，并再次运行验证安全复用和旧指标归档。
其生成清单为第 2 版，声明的批次号与三个核心文件指纹重算一致，下游定位和评估也
记录同一个批次号。它能证明：当前
Sionna/DeepMIMO API 能运行、UE/BS 角色与数组形状一致、原始网格能在预先固定的
范围内生成可反向追踪的二维墙、定位配置和在线输入不含真值，而且三阶段产物可以
完整落盘并由运行编号和文件指纹绑定。此次位置误差为 0.1604 m，时间偏差误差为
0.0898 ns。

它不能单独证明算法已经具有科学上的稳定精度。正式验证至少还需要多 UE 位置、
多随机种子、信噪比与公共偏差扫掠、漏检和虚警实验、几何退化场景、基线方法、
统计覆盖率以及真实 CSI。一次 smoke 成功或一次误差较小，都只能算工程检查通过。
