## 02 · 助手

这篇 **SpotFi: Decimeter Level Localization Using WiFi** 是 2015 年 SIGCOMM 的经典工作。它的核心目标很明确：

> **只使用普通商用 WiFi 网卡提供的 CSI，在不修改硬件、不要求发射端和接收端严格时间同步的情况下，实现亚米级室内定位。**

论文使用 Intel 5300，AP 端只有 **3 根天线**，但最终在典型室内办公环境中做到约 **0.4 m median localization error**。[来源 1][source_1]

这篇论文和你现在讨论的 **AoA + Delay/ToF + 时间同步误差** 问题其实非常相关。尤其值得注意的是：**SpotFi 明确承认它估计出来的 ToF 不是绝对真实 ToF，因此最终根本不用 ToF 做测距。**

### 1. SpotFi 首先解决的问题：只有 3 根天线，MUSIC 怎么分辨多径？

普通 AoA-MUSIC 的基本限制是：

\[
N_{\text{antenna}} > N_{\text{path}}
\]

或者至少阵列自由度要足够大。

但 Intel 5300 只有 3 根天线，而室内可能有 4、5 条甚至更多显著多径。因此，如果单纯做

\[
\text{CSI across antennas}
\rightarrow
\text{AoA MUSIC},
\]

三根天线的分辨能力是不够的。论文也明确把这个问题作为出发点。[来源 1][source_1]

SpotFi 的核心想法是：

**不要只利用天线维度，还要利用 OFDM 的子载波维度。**

因为一条路径的 AoA 会在不同天线上形成相位差：

\[
\Delta\phi_{\text{antenna}}
\propto
\frac{2\pi d\sin\theta}{\lambda},
\]

而一条路径的传播时延 \(\tau\) 会在不同子载波之间形成相位斜率：

\[
\Delta\phi_{\text{subcarrier}}
=
-2\pi\Delta f\tau.
\]

所以 CSI 实际同时携带：

\[
\boxed{\text{antenna dimension}\rightarrow AoA}
\]

和

\[
\boxed{\text{subcarrier dimension}\rightarrow ToF}.
\]

于是 SpotFi 不再做一维 MUSIC，而是联合搜索

\[
\boxed{P_{\text{MUSIC}}(\theta,\tau)}
\]

也就是你现在经常提到的 **AoA-Delay 二维联合 MUSIC**。论文算法最终就是在二维 MUSIC 谱上找峰，每个峰对应一条候选传播路径。[来源 1][source_1]

---

### 2. 它最有意思的 trick：Antennas × Subcarriers 构造“虚拟阵列”

Intel 5300 输出：

\[
3\text{ antennas}\times30\text{ subcarriers}.
\]

SpotFi 的观察是，如果把不同的

\[
(m,n)
=
(\text{antenna index},\text{subcarrier index})
\]

看作不同的“sensor”，理论上就有

\[
3\times30=90
\]

个观测位置，而不是只有 3 个阵元。[来源 1][source_1]

当然，不能简单把这 90 个数塞进 MUSIC，因为这些观测之间高度相关，矩阵可能秩不足。

所以作者又做了一个 **CSI smoothing**。

论文 Figure 4 是整个 SpotFi 比较关键的一张图：

他们通过在“天线 × 子载波”二维网格上滑动子阵，构造很多结构相同、位置不同的虚拟子阵列，最终形成一个 **smoothed CSI matrix**。

例如实验配置里最终可以构造出大约

\[
X\in\mathbb C^{30\times30}.
\]

然后对

\[
XX^H
\]

做特征值分解，再按照标准 MUSIC 的方式获得噪声子空间 \(E_N\)，计算

\[
P_{\mathrm{MU}}(\theta,\tau)
=
\frac{1}
{
a^H(\theta,\tau)
E_NE_N^H
a(\theta,\tau)
}.
\]

因此它本质上是：

\[
\boxed{
CSI
\rightarrow
二维虚拟阵列
\rightarrow
Spatial/CSI smoothing
\rightarrow
2D MUSIC
\rightarrow
\{(\theta_k,\tau_k)\}
}
\]

论文 Figure 3–4 对这个过程进行了比较完整的解释。[来源 1][source_1]

这实际上就是 SpotFi 最核心的 signal processing contribution。

---

### 3. 但这里马上遇到了你最近一直研究的问题：WiFi 根本没有严格时间同步

假设真实路径是

\[
\tau_k.
\]

WiFi CSI 中看到的实际上更接近

\[
\hat\tau_k
=
\tau_k+b,
\]

这里的 \(b\) 包含 **Sampling Time Offset (STO)**、packet detection delay 等。

而且由于 Tx 和 Rx 的 sampling frequency 也有偏差，\(b\) 甚至会随 packet 改变。论文明确指出：

> sender 和 receiver 没有时间同步，因此估计出来的 ToF **不能表示 target 到 AP 的真实传播时间**。[来源 1][source_1]

这个地方和你的模型

\[
\tau_i^{obs}
=
\frac{L_i(p)}{c}
+
b
+
\epsilon_i
\]

几乎是一个思想。

SpotFi 的处理方式并不是把 \(b\) 真正估计出来。

它做的是 **phase sanitization**。

因为公共时间偏移 \(b\) 在频域 CSI phase 上体现为一个关于子载波频率的 linear phase：

\[
\phi_n^{bias}
=
-2\pi f_n b.
\]

因此 SpotFi 对 CSI 的 unwrapped phase 拟合一条直线，然后把这个 linear component 去掉。[来源 1][source_1]

但这里有一个非常重要的区别：

\[
\boxed{\text{SpotFi 去掉的是 packet-to-packet 的变化，并没有恢复绝对 ToF。}}
\]

作者自己说得非常清楚：

> sanitization 可以把不同 packets 的 ToF 对齐到一个共同的 STO，但 **does not give us the true ToF**；要获得真实 ToF，需要 ns 级节点同步。[来源 1][source_1]

因此 SpotFi 最终 **拒绝用 ToF 来测距离**。

这个结论对你现在的研究非常重要。

---

### 4. 那 SpotFi 算出来的 ToF 到底干什么？

它只把 ToF 当作一个 **multipath discriminator**。

它发现：

真实的 direct path 往往在连续多个 packets 中比较稳定：

\[
(\theta_k,\tau_k)
\]

会形成一个比较紧密的 cluster。

而反射路径、噪声峰、错误 MUSIC peak 往往变化较大。

于是 SpotFi 收集多个 packet 的

\[
(\theta,\tau)
\]

点，然后在 AoA-ToF 二维空间聚类。

对第 \(k\) 个 cluster 定义一个 direct-path likelihood，大概形式是

\[
L_k=
\exp
\left(
w_C C_k
-w_\theta\sigma_{\theta,k}
-w_\tau\sigma_{\tau,k}
-w_s\bar{\tau}_k
\right).
\]

其中考虑了：

\[
\text{cluster points 数量},\quad
\sigma_\theta,\quad
\sigma_\tau,\quad
\bar\tau.
\]

直觉就是：**点越多、AoA 越稳定、ToF 越稳定、ToF 越小，这条路径越可能是 direct path。**

最终选

\[
k^*=\arg\max_k L_k
\]

作为直达径。[来源 1][source_1]

所以 SpotFi 其实没有把 ToF 当成“range measurement”，而是当成：

\[
\boxed{\text{path identification feature}}
\]

这一点很容易在第一次读论文的时候看错。

---

### 5. 最后的定位反而很传统

假设有多个 AP。

每个 AP 最终给 SpotFi：

\[
\theta_i
\]

也就是估计的 direct-path AoA，以及对应的 confidence \(l_i\)。

另外 AP 还能提供 RSSI。

SpotFi 最后求一个位置 \(p\)，让这个位置预测出来的 AoA 和 RSSI 尽可能匹配观测：

\[
\min_p
\sum_i
l_i
\left[
(\bar p_i-p_i)^2
+
(\bar\theta_i-\theta_i)^2
\right].
\]

注意这里：

\[
\boxed{\text{Localization = AoA + RSSI}}
\]

而不是

\[
\text{AoA + ToF}.
\]

ToF 到这里已经退出定位公式了。论文明确解释，这是因为它没有办法获得绝对传播 ToF。[来源 1][source_1]

整篇 SpotFi 的 pipeline 因此可以压缩成：

\[
\boxed{
CSI
\rightarrow
AoA\text{-}ToF\;2D\ MUSIC
\rightarrow
多 packet 聚类
\rightarrow
识别 Direct Path
\rightarrow
Direct\ Path\ AoA + RSSI
\rightarrow
多 AP 定位
}
\]

实验使用 Intel 5300、5 GHz、40 MHz 带宽、3 天线、30 个 CSI 子载波。典型办公室环境 median 定位误差约 **0.4 m**；只有两个 AP 有较可靠 direct path 的困难环境中约 **1.6 m**；走廊环境约 **1.1 m**。[来源 1][source_1]

---

### 对你现在研究最值得注意的一点

我认为你读 SpotFi 时最应该抓住的不是“40 cm WiFi localization”，而是下面这个逻辑：

\[
\boxed{
\text{SpotFi 已经从 CSI 联合估计了 AoA + ToF}
}
\]

但是因为

\[
\hat\tau_k
=
\tau_k+b,
\]

作者最后选择：

\[
\boxed{
不估计 b
\rightarrow
不使用绝对 ToF
\rightarrow
只拿 ToF 帮助识别路径
}
\]

而你现在研究的方向恰恰可以理解为：

\[
\boxed{
不要把这个 b 扔掉，而是利用场景几何/RT 把 b 反过来估计出来。
}
\]

也就是说，SpotFi 遇到的同步问题和你遇到的是同一个物理问题，只不过 **SpotFi 选择绕开它，你试图直接求解它**。

这也是为什么我认为这篇 2015 年的论文对你当前的 **“AoA + Delay + geometry → joint position/time-bias estimation”** 特别值得细读。尤其是它 Section 3.1 的 **AoA-ToF MUSIC** 和 Section 3.2.2 的 **ToF sanitization**，基本就是与你现在工作最直接相关的两个部分。[来源 1][source_1]

## 1. 这篇到底是什么？

论文是：

**Ojas Kanhere, Theodore S. Rappaport, "Map-Assisted Millimeter Wave and Terahertz Position Location and Sensing," IEEE TWC, 2025.**

核心方法叫：

\[
\boxed{\text{MAP-AT: Map-Assisted Positioning with Angle and Time}}
\]

它的目标就是：

> 已知环境地图 + BS 位置，利用多径的 **AoA/AoD + ToF**，在 LOS/NLOS 下定位 UE，而且允许 **multi-bounce reflection**。[来源 2][source_2]

值得注意的是，这个核心想法甚至不是 2025 才出现的。论文自己的参考文献显示，他们在 **GLOBECOM 2019** 就已经发表过 *Map-Assisted Millimeter Wave Localization for Accurate Position Location*。2025 TWC 是明显扩展后的版本。[来源 2][source_2]

所以这个 prior art 要从 **2019 年**算起，而不是 2025。

# 2. 更关键的是：它的系统设定几乎和你的 uplink 设定一样

论文明确讨论两种情况：

- UE 是 RX：使用 **ToF + AoD**
- UE 是 TX：使用 **ToF + AoA**

你现在正是：

\[
UE\rightarrow BS
\]

UE 发上行信号，BS 接收，然后提取 AoA + Delay。

因此对你而言，MAP-AT 对应的就是：

\[
\boxed{
UE~TX
\rightarrow BS~RX
\rightarrow \{\mathrm{AoA}_i,\mathrm{ToF}_i\}
\rightarrow Map
\rightarrow UE~position
}
\]

论文甚至直接写了：

> 当用户是 transmitter 时，用 BS 估计到的 ToF 和 AoA 做同样的定位流程。[来源 2][source_2]

这一点已经不是“像”，而是**系统模型高度重合**。

---

# 3. MAP-AT 的核心算法，其实和你最初的“反向 RT”想法也很接近

假设 BS 收到一条 MPC：

\[
z_i=
(\theta_i,\tau_i)
\]

有：

\[
d_i=c\tau_i.
\]

MAP-AT 从 BS 开始，沿着观测到的 AoA 方向**反向追踪**。

遇到墙以后怎么办？

它不知道这条路径到底：

- 穿过去了；
- 反射了；

所以两种情况都保留。

继续往后走，又遇到一堵墙，再产生：

\[
reflection/transmission
\]

两个分支。

于是：

\[
1\rightarrow2\rightarrow4\rightarrow8\rightarrow\cdots
\]

一直追踪，直到累计传播距离达到：

\[
L=d_i=c\tau_i.
\]

每一个可能的 endpoint 都叫做一个：

\[
\boxed{\text{Candidate Location}}
\]

也就是候选 UE 位置。[来源 2][source_2]

论文 Figure 3 就是在讲这个东西：

三个 MPC 各自产生很多候选位置：

\[
\mathcal C_1,\mathcal C_2,\mathcal C_3
\]

虽然每条路径会产生错误候选，但**真实 UE 位置会被不同 MPC 重复命中**。

因此最终：

\[
p^*
=
\text{cluster with maximum number of MPCs}
\]

然后取这个 cluster 的 centroid：

\[
\hat p=
\frac{1}{|\mathcal C^*|}
\sum_{q\in\mathcal C^*}q.
\]

论文明确说，ToF/AoD 有误差以后，各条路径得到的位置不会严格重合，所以把附近的 candidate locations 聚类，然后选成员最多的 cluster。[来源 2][source_2]

# 5. 但是——它恰恰没有解决你现在最关心的问题

这里才是最重要的区别。

MAP-AT 的基本模型相当于：

\[
\boxed{
\tau_i^{obs}
=
\frac{L_i(p,h_i)}{c}
+
\epsilon_i
}
\]

或者：

\[
d_i^{obs}
=
L_i(p,h_i)
+
e_i.
\]

也就是说它认为：

\[
c\tau_i
\]

就是这条路径的传播长度，只不过带一点测量噪声。

所以它能够直接说：

\[
L_i=c\tau_i
\]

然后沿射线走这么远。

论文对 ToF error 的模型也非常明确：

\[
e_{\tau,i}\sim
\mathcal N(0,\sigma_{\tau,i}^2)
\]

并根据 bandwidth、SNR 和 CRLB 构造这个标准差；例如他们给出的 1 GHz、10 dB 情况下，ToF/ranging 标准差约对应 10 cm。[来源 2][source_2]

注意这里的：

\[
\boxed{\text{zero mean}}
\]

非常重要。

---

## 而你的模型是：

\[
\boxed{
\tau_i^{obs}
=
\frac{L_i(p,h_i)}{c}
+
b
+
\epsilon_i
}
\]

其中：

\[
b
\]

是同一个 CSI observation window 内所有路径共享的 unknown bias。

因此：

\[
c\tau_i^{obs}
=
L_i(p,h_i)
+
cb
+
c\epsilon_i.
\]

假设：

\[
b=100\text{ ns}
\]

那么：

\[
cb\approx30\text{ m}.
\]

MAP-AT 会直接认为：

\[
L_i^{obs}=L_i+30\text{ m}
\]

然后每条反向射线都多走 30 m。

这就不是简单的“measurement noise”了。

这是：

\[
\boxed{\text{systematic common-mode error}}
\]

而且所有路径共享。

论文全文我专门搜索了 **clock** 和 **synchronization**，没有看到相应的 clock-bias 联合估计模型。相反，作者直接把 ToF 当作已知可测量量。[来源 2][source_2]

# 6. 更有意思的是，它其实绕过了你研究的问题

论文说 ToF 可以通过：

\[
\text{round-trip time}
\]

或者

\[
\text{one-way propagation time}
\]

得到。[来源 2][source_2]

这两个东西区别很大。

### RTT / TWR

如果做：

\[
TX\rightarrow RX\rightarrow TX
\]

通过协议设计消除 turnaround delay 等因素，那么 clock offset 可以一定程度被消掉。

也就是说，它可以避开：

\[
b_{TX}-b_{RX}.
\]

这和你直接从**单向 CSI**中估计 Delay 是完全不同的问题。

### One-way ToF

如果直接做：

\[
UE\rightarrow BS
\]

那么除非两端高度同步或经过校准，否则就会变成：

\[
\tau_i^{obs}
=
\tau_i+b.
\]

而 MAP-AT 并没有进一步处理这个 \(b\)。

所以准确地说：

\[
\boxed{
\text{MAP-AT assumes usable absolute ToF;}
}
\]

你的问题是：

\[
\boxed{
\text{what if absolute ToF is unavailable because of synchronization bias?}
}
\]

这确实是不同的问题。

---

# 7. 而且我发现这篇文章有一个对你非常有利的实验细节

它标题和实验部分容易让人产生一种印象：

> “他们直接拿真实 mmWave measurement 的 AoA + ToF 验证了 MAP-AT。”

但仔细看并不是完全这样。

在他们自己的 **28 GHz / 140 GHz indoor + factory measurements** 中：

MAP-AT 是一个明确的 **三维定位方法**，不是二维方法。

\mathbf p=[x,y,z]^T

三个坐标；每条多径还包含三维散射/反射几何。[来源 3][source_3]

\text{azimuth}+\text{elevation}

\boxed{

- \(\theta_i\)：elevation；
- \(\tau_i\)：ToF。

你现在做的是一个 **二维简化问题**：

\[
\mathbf p=[x,y]^T

\[
(\theta_i,\tau_i)

一个平面 AoA + Delay。

\[
\text{MAP-AT: }
(x,y,z)
+
(\text{azimuth},\text{elevation},\tau)
\]

而你现在是：

\[
\text{你的模型: }
(x,y)
+
(\text{AoA},\tau+b).
\]

> **“我做二维、MAP-AT 做三维”本身绝对不能算你的创新点。**

因为把一个 3D 定位问题限制到 2D 通常只是降低问题维度，甚至属于更简单的特殊情形。

这个未知公共 \(b\)。

\[
\boxed{
\tau_i^{obs}

}

> “MAP-AT 是 3D，我们是 2D。”

> **MAP-AT considers 3D map-assisted localization under usable absolute ToF measurements, whereas our current formulation studies asynchronous map-assisted localization where all observed path delays contain an unknown common timing offset.**

这才是本质差异。[来源 3][source_3]

\[

\text{LoS}
+
\text{specular reflection}
+
\text{transmission}

\[
\text{LoS}
+
\text{reflection}
+
\text{transmission}
+
\text{diffraction}.
\]

}

\]

重新设计完整算法，在 reflection / diffraction coexistence 下联合估计位置和 bias。

可以形成论文，但创新性还要看方法深度。

**真正值得冲的方向：**

\[
\boxed{
\begin{aligned}
&\text{Asynchronous}\\
+&\text{single-BS}\\
+&\text{AoA + biased Delay only}\\
+&\text{known map}\\
+&\text{unknown path topology}\\
+&\text{reflection/diffraction}\\
\rightarrow&\quad
\text{joint }(\mathbf p,b,\mathbf h)
\end{aligned}}
\]

然后再加一个非常重要的东西：

\[
\boxed{\text{Identifiability / Observability Analysis}}
\]

即回答：

> 在什么条件下，仅凭这些多径，位置 \(p\) 和时间偏差 \(b\) 是可以被唯一解出来的？

比如：

\[
K\ge ?
\]

需要几条 MPC？

只有反射能不能解？

只有绕射呢？

reflection + diffraction 是否提高可辨识性？

哪些地图几何会产生：

\[
(p_1,b_1)\neq(p_2,b_2)
\]

却产生相同的：

\[
\{AoA_i,\tau_i\}?
\]

如果你能把这一层做出来，我会认为论文的学术价值就明显不再是：

> “MAP-AT 加两个功能。”

而变成：

> **提出并解决一种新的 asynchronous map-constrained multipath localization problem。**

这两者在审稿人眼里的区别非常大。

所以现阶段我的判断是：**方向值得继续，但不要把创新性建立在“我比 MAP-AT 少两个先验假设”这句话上。应该建立在“放宽这些假设以后出现了一个新的联合估计与可辨识性问题，并且现有方法无法解决”上。**

而且我建议你下一篇重点读的已经不是 MAP-AT 了，而是刚才找到的 **Li et al., IEEE WCL 2023, *An Iterative 5G Positioning and Synchronization Algorithm in NLOS Environments With Multi-Bounce Paths***。它可能比 MAP-AT **更直接威胁你当前的 novelty**，我们有必要把它和你的方案逐公式比较一次。[来源 5][source_5]
